# 成交容量风险预警与动态拆单

本模块回答：按照当前执行进度和已观察到的成交量，剩余订单是否还有足够的成交容量？如果后续容量偏紧，现在是否需要加快？它是事后容量回放研究，尚未连接券商或交易所。

## 使用

按 README 的命令启动本地面板，上传已转换为纽约时间的一分钟 CSV。在第 06 区选择“新增：成交风险预警与动态拆单”，设置回看窗口、最多评估日期数、订单占历史平均日量的比例和参与率上限，开始验证。

同一目标日的三种方案使用相同数量、截止时间和参与率：固定均匀、固定历史成交量分配、动态风险预警。未完成数量始终保留。成本表同时显示假设冲击成本；只有三种方案都完成的同一组日期才进入共同完成成本对照。不以少成交来声称省钱。

结果可切换日期并移动时间滑块。每个点显示该五分钟开始前的剩余容量场景、剩余订单和本期尝试数量；该时段回放完成后的成交量另行标明。报告按钮依据实际任务类型导出离线 HTML、Markdown 和完整 JSON。关闭页面不会取消后台计算，但重新打开页面目前不会自动恢复任务选择。

## 计算方法

1. 对每个目标日，只使用此前 2–20 个完整上传交易日，最多评估最近 60 日。原文件指纹、适配文件内容会重新核对，沿用原有缺失与交易时段规则。
2. 第 t 个五分钟开始前，只读取当天前 t 个已结束时段。每条历史剩余量路径乘以 `(当天已发生累计量 + 先验量) / (该历史日此前累计量 + 先验量)`。先验量为训练窗口平均每五分钟成交量的三倍。
3. 对这些路径按参与率取整数成交容量，得到剩余容量的经验 p10、中位数和 p90。容量覆盖场景占比是“总容量至少覆盖剩余数量”的历史场景比例，只表示必要容量条件。另计算冻结当前后续释放计划后的完成场景比例；未来继续重新规划会改变结果。
4. 本期通常按剩余预测量比例分配；若“剩余订单减去本期之后容量 p10”更大，则提高本期尝试数量。任何时候都不增加总订单、不放宽参与率、不自动延长截止时间。未成数量下一期重新规划。
5. 决策完成后，回放器才用该五分钟实际总量按参与率取整限制成交量。实际整数容量用十进制运算取整，避免例如 100 × 29% 被浮点误差算成 28。预测场景容量近似计算，不是交易保证。

## 如何判断是否有用

完成率之外，还要看剩余数量、假设冲击成本、相同共同完成日期的基点缺口，以及预警是否足够早。动态方案可能更贵，也可能完成得更差；应保留失败日期，不在看到评估结果后挑参数或日期。

区间在目标日事后检查，但这些未来结果不进入当时决策。在事先固定的开盘后 0、60、195、300、385 分钟分别统计有多少日期的实际剩余容量落入 p10–p90 区间；同时保留全时点覆盖率。容量覆盖场景占比的 Brier 诊断仅统计仍有待卖数量的决策，衡量它与后来容量是否足够的一致程度，不是实际成交成功概率的校准证明。同日多个时点相互依赖，不能当成独立交易日。

## 局限

经验分位数不是置信区间，p10–p90 不保证未来覆盖 80%，历史场景占比也不是已校准概率。2–20 日窗口尤其容易低估尾部变化。本模块尚未实现更长窗口的概率再校准。

成交仍按事后五分钟总量和收盘价假设，不含订单簿、排队、手续费、价差、逐笔延迟或撤单成本。冲击系数固定为 0.00001，未用真实成交拟合；剩余股票按期末价计价不代表卖出。三种方案的释放/重新规划规则是研究假设，不能直接等同于实际限价订单生命周期。

未增加任何新的真实数据来源。使用已有本地行情时，小样本实验结果仅保存在外部输出目录；原有冻结研究不作改写。数据仍须符合使用条件，不自动上传或发布。

## 代码入口

- `tools/adaptive_execution.py`：场景、决策、回放、滚动对照和区间检查。
- `tools/workflows.py`：复用上传核验、后台任务、状态与报告类型核对。
- `tools/adaptive.js`：结果、时间轨迹和读取失败时的清理。
- `tools/adaptive_reports.py`：独立中文离线报告。

动态成交量更新可参考 [Busseti 与 Boyd 的 VWAP 执行研究](https://web.stanford.edu/~boyd/papers/vwap_opt_exec.html)。本项目采用的是明确的经验场景和容量预留规则，不声称复现该论文算法或构成新的最优性证明。代码与研究整理使用 AI 辅助。
