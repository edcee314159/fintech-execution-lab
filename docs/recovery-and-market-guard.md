# 订单恢复与异常行情保护

在本地面板第06区分别展开“断线与重复回报恢复”和“异常行情与停复牌保护”。所有券商、订单、行情及故障在本机人工生成，没有真实账户或实时行情连接。

两项是可复用机制与独立故障实验，**不是给所有旧模块开启的全局实盘保护**。行情门控仅控制本实验的新IOC子单；已有挂单仍可能在撤单生效前成交，该风险由订单恢复实验单独检验。

## 第三项：断线与重复回报恢复

tools/order_recovery.py 提供模拟券商、事件日志和状态重建。

1. 先保存稳定编号的下单意图，再发送。意图一经保存就占用数量；确认丢失不代表可以换编号重发。
2. 可新增量 = 母单 − 已确认成交 − 仍可能成交的预留；未连接或未核实时显示0。已确认成交与预留之和不得超过母单。
3. 按唯一成交ID去重；相同ID内容冲突则暂停。同一订单的累计状态和成交明细取较大的已知值，不能相加。旧累计回报不能倒退已知成交。
4. 撤单在途继续预留。单条取消回报不释放额度，完整一致的终态快照才释放。已确认终态的成交量不能被后续快照改写。
5. 对账必须覆盖此母单全部订单、完整成交与持仓，且快照序号递增。未知订单在列表中缺失不是“未被接收”的证据。
6. 重启逐条重建后仍须重新连接、对账。日志破损、尾部不完整、指纹不一致或写锁遗留时停止，不自动截断或解除。

日志在当前输出目录 rolling/任务编号/orders.jsonl，每条包含序号、前序指纹、事件和SHA-256。写入、刷新并请求fsync后才更新内存；单写者锁及写前版本核对防止并行覆盖。指纹用于意外修改检查，不是防攻击签名，也不构成无限的断电持久性保证。

人工情形包括确认丢失、撤单在途、混合故障（含重启）及快照缺失未知订单。最后一种故意保持暂停和未完成。“无保护超时重发”是故意缺少检查的失败示例；两条轨迹步骤不同，不作速度或收益排名。实际成交和实际持仓只用于事后核对，恢复器断线时不会偷看券商内部状态。

模拟券商假定稳定意图ID、完整且原子的母单范围快照、无外部交易及完整成交明细。真实接口可能不满足这些契约；多账户、手工订单、成交冲正、更正和历史缺失尚未支持，矛盾时停止核实。不能据此宣称跨券商“恰好执行一次”。

## 第四项：异常行情与停复牌保护

tools/market_guard.py 的 MarketGuard 仅依据已收到的事件判断：

- 报价须为正整数分价格，买价低于卖价，源时间不来自未来或倒退，序号单调。重复或过期序号不能刷新有效期。
- 序列缺口、交叉报价及未来时间会暂停，需要显式人工重同步快照；后续普通更新不证明缺口已修复。快照标记真实性是本模型契约。
- 报价年龄超出配置秒数或缺少有效成交量时暂停。年龄上限以内的有效旧报价仍可用，不把每次短暂停更都判成停牌。
- 独立人工状态通道区分未知、停牌、只报价与可交易，使用递增状态序号。旧状态不能解除新停牌；只报价不是交易恢复。没有状态变化时保留最后有效状态，尚未接实际状态通道或其健康监控。
- 零成交量是有效的0，不据此推断停牌；容量预测和成交容量可以为0。
- 暂停后先观察两条合格新报价，再按配置步数逐步恢复到子单上限。只有新可接受序号增加观察计数；年龄仍合格时累计，真正暂停时清零。

每次240秒。请求依据累计均匀进度、恢复比例、子单上限以及上一秒已收到成交量的参与量预测；实际成交受本秒事后人工容量限制，不提前读取未来成交量。

无状态检查对照故意不遵守暂停或追单上限。两者共享母单、截止及事后参与量上限；物理停牌、只报价和闭市时，两者都不虚构成交。“保护规则外尝试”只是按本模块本应暂停却提交的次数，不是交易所违规认定。未完成余量保留，不保证完成。
