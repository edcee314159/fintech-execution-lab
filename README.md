# FinTech Execution Lab：大额订单拆分研究

一大笔股票卖单，应该一次卖完，还是分几次卖？每次卖多少、隔多久卖一次？这个项目用 Python 建立模型、运行模拟，并结合历史成交量，研究这些问题。

这个工具关注的是**怎样执行一笔已经决定要卖出的订单**。卖得太集中，可能压低成交价格；卖得太慢，手里还没卖掉的股票又会面临价格波动。项目比较不同的拆单方式，观察它们在交易成本、价格风险和完成订单方面的差别。

## 项目能做什么

- **生成卖出计划。** 给定股票数量、交易时长、价格波动等条件，计算各个时间段应卖出多少股，并与“每隔一段时间卖出相同数量”的方法比较。
- **比较成本和风险。** 模拟多条可能的价格路径，观察平均成本、结果的波动，以及比较结果有多不确定。这种反复随机模拟的方法叫作“蒙特卡洛模拟”。
- **检查模型是否可靠。** 改变参数，故意使用不准确的参数，并让不同求解方法计算同一个问题，检查结果是否一致、计算需要多长时间。
- **考虑市场成交量。** 为每个时间段设置卖出上限，例如最多占该时段市场成交量的 10%，检查订单能否在规定时间内完成。
- **用历史数据检验计划。** 使用 SPY、AAPL 的日内成交量，只根据此前的交易日制定计划，再用之后实际记录的成交量检查计划的完成情况。

历史成交量实验使用每个目标日之前的 5 个完整交易日预测成交量，比较 3 种预测方法、3 种订单大小和 3 种拆单方法。订单大小按过去的平均每日成交量确定。

这次实验覆盖 2 个标的、5 个评估日期，共生成 **30 份成交量预测、270 条方案记录**。其中 264 条成功生成计划，229 条在历史成交量回放中完成；35 条计划结束时仍有股票未卖出，另外 6 条因预测容量不足而未生成计划。

这些数字说明，在预测成交量下可行的计划，到了后续交易日也可能无法完成。同一个交易日被用于多种方案比较，因此 270 条记录并不代表 270 个独立交易日。详细结果见[完整研究报告](results/real-volume/research-note.md)。

## 金融方法与编程实现

金融部分研究交易对价格的影响、未卖出持仓的价格风险、成交量预测，以及市场容量对订单的限制。模型会在预期成本和成本波动之间作权衡，并比较按时间均匀卖出、按成交量分配卖出等方法。

编程部分负责数值求解、随机模拟、历史数据处理、结果核对和图表生成。代码被打包为可安装的 Python 工具，并配有自动测试，让同一组条件下的实验可以重新运行和检查。

## 如何安装和运行

已经验证的运行环境是 **Windows 和 Python 3.12**。在仓库根目录打开 PowerShell，运行下面的命令。安装和实验输出目录应放在仓库之外，并使用尚未存在的新目录。

```powershell
python tools/bootstrap.py --workspace D:\Codex\FinTech-Execution-Lab\install --test
```

这条命令会构建安装包、创建独立的 Python 环境、安装固定版本的依赖，随后运行全部测试，并对前八项研究做快速运行检查。首次安装需要联网；已有离线依赖目录时，可以使用 `--wheelhouse`。生成的文件会保存在指定的外部目录。

安装完成后，可以依次查看可运行的研究、检查环境，以及运行前八项完整研究：

```powershell
D:\Codex\FinTech-Execution-Lab\install\venv\Scripts\python.exe -m execution_research list
D:\Codex\FinTech-Execution-Lab\install\venv\Scripts\python.exe -m execution_research doctor
D:\Codex\FinTech-Execution-Lab\install\venv\Scripts\python.exe -m execution_research run all --output D:\Codex\FinTech-Execution-Lab\full-run
```

可用命令包括 `execution-lab`、`execution-lab-research` 和 `execution-volume-validate`。快速运行检查用于确认工具能正常工作；完整研究使用项目内保存的固定实验设置。每次运行请使用新输出目录，保留此前结果。

真实成交量实验还需要单独准备市场数据，步骤见[真实成交量实验说明](docs/real-volume.md)。原始 FirstRate Data 行情和本地价格、成交量数组没有上传；公开结果保留了衍生指标、拆单计划和图表。数据供应商可能替换样本文件，程序会核对文件指纹，拒绝把变化后的数据当成原来的实验输入。

## 打开交互实验面板

安装完成后，在仓库根目录运行：

```powershell
D:\Codex\FinTech-Execution-Lab\install\venv\Scripts\python.exe tools/dashboard.py --output D:\Codex\FinTech-Execution-Lab\dashboard-runs
```

在浏览器打开 **http://127.0.0.1:8765**，调整订单数量、交易时长、价格波动和风险权重，点击“运行并比较”。面板会展示均匀卖出与模型拆单的计划曲线、剩余持仓、理论成本、风险和模拟结果，并支持下载 JSON 结果与 CSV 拆单计划。

面板复用现有 Python 模型，无需额外安装界面依赖；仅监听本机。每次实验以新文件保存到 `--output` 指定的仓库外目录。关闭终端中的程序后，本地面板会停止。可用 `--port` 更换端口。

这是基础模型的交互入口，假设计划全部成交，不能据此判断真实市场中的订单完成率。面板最多支持 120 个时段、2000 次模拟，且模拟次数 ×（时段数 + 1）不超过 120000。相同参数和随机种子产生相同结果；修改参数后需要重新运行。

### 历史成交过程回放

同一面板中的“历史成交过程回放”使用已公开的 SPY、AAPL 衍生实验结果，无需下载原始行情。可按标的、日期、预测方法、订单占比和拆单方法切换全部 270 条情形，并拖动时间滑块、播放或跳到收盘。

四项数字分别显示累计计划卖出量、累计模拟完成量、整笔订单剩余量和已到期未完成的积压量。默认展示一个未完成的例子；229 条完成、35 条仍有剩余、6 条未生成计划的情形全部保留。未生成计划时显示说明，不绘制虚构曲线。

回放与左侧参数实验分开，左侧参数不会改变固定历史结果。它是基于事后成交量的容量检查，不代表交易所真实成交；只读取公开的计划、模拟完成量和剩余量，不提供原始价格或成交量文件。

### 自定义行情 CSV 上传与检查

面板中的“上传自己的行情 CSV”支持单个标的的 UTF-8 CSV，最多 5 MiB、100000 条数据行。输入为一分钟行情，时间须事先转换为纽约本地时间；可有表头，也可使用无表头的六列顺序：

```csv
timestamp,open,high,low,close,volume
2026-09-21 09:30:00,100,101,99,100,1000
2026-09-21 09:31:00,100,101,99,100,1200
```

以上只是人工生成的两行格式示例，不是完整交易日。界面会检查时间、列数、价格关系、有限整数成交量、重复记录、时间逆序和缺失分钟，并显示问题行号和逐日完整性。成交量超过当日正成交量中位数 20 倍仅作复核提示，不自动删除。

上传文件仅保存在启动命令指定输出目录的 `uploads/<随机编号>/` 下：`source.csv` 原样保留，`audit.json` 保存报告。通过格式检查时另存 `loader-input.csv`，供原有行情读取器使用；仅移除表头、调整列序和首尾空白，保留重复行供读取器按原规则处理。该适配文件会与现有读取器交叉核对。原文件指纹记录在报告中，报告可在面板下载。

当前完整性规则为纽约本地时间 09:30–15:59 共 390 个分钟，不补缺失、不自动排序、不替换异常值；盘前盘后单独计数。工具不识别整日缺失、节假日或提前收盘。至少六个完整且非全零成交量的交易日，只代表满足五日回看加一日评估的最低数据准备条件，不会自动生成新实验，也不会改变已有回放或冻结结果。格式通过不代表数据真实、覆盖全市场或已获得使用授权。

### 滚动验证：使用更长的自定义历史

上传检查完成后，进入“上传数据的滚动验证”，选择本机数据，设置 2–20 个完整交易日的回看窗口、最多 1–60 个评估日、订单占比和成交参与上限。程序固定使用最后一段连续可用的上传完整日，每个目标日只根据此前窗口制定计划；数据不足时明确报错，不补造日期或隐藏失败情形。

验证在后台运行，页面显示阶段和状态，可重新查询任务。结果包含三种成交量预测与三种拆单方法的计划数、完成数和剩余量；完成率分母包括未生成计划的情形。原文件、适配文件会重新核对指纹和内容，防止变更后的数据继续沿用旧检查结果。影响系数与风险权重固定为 0.00001，均未用真实成交校准。

按成交量或价格波动的分组仅是事后描述：目标日与过去窗口的中位数比较，低于 0.8 倍为低、高于 1.2 倍为高；这些标签不用于当日下单。不同方案可能共享同一日期，不能当作相互独立的市场样本。数据范围以实际上传内容为准；目前没有因新增此功能而增加真实长样本证据，人工测试不能代替真实行情验证。

如需读取此前输出目录中已检查的上传文件，可在启动命令添加 `--uploads-from D:\Codex\FinTech-Execution-Lab\previous-runs`。该目录作为输入读取，新任务写入当前 `--output` 目录的 `rolling/<任务编号>/`，不改动原有冻结研究。任务中的“可用交易日”仍沿用当前数据检查规则，不代表已核实交易所日历或整日缺失。

### 一键生成中文实验报告

基础实验运行后，或滚动任务成功后，点击对应的“生成报告”。生成器读取已保存的实验记录，整理实际参数、数据范围、图表、未完成情况和局限，并保存记录指纹。未重新运行的新参数不会混入旧结果报告。

每份报告在输出目录的 `reports/<报告编号>/` 保存三份文件：`report.html` 是无需外部资源的完整图文报告，可离线阅读和用浏览器打印；`report.md` 是便于编辑的文字版，图表见 HTML；`evidence.json` 是完整数值依据。价格诊断只在同一预测方法和订单大小下、三种拆单方法共同完成的日期比较，不把不同子样本作跨预测方法成本排名。

报告和上传数据均只保存在本机，不自动提交到 GitHub。只发布功能代码，人工示例与用户行情不会作为新的公开市场实证。

## 阅读结果时需要注意什么

这是一个采用简化假设的研究工具。基础模型只研究卖单，并假设计划中的交易都能成交；带成交量限制的实验进一步检查数量是否能完成，但历史回放也不能证明真实下单一定能成交，更不能证明可以盈利。

部分成交量实验使用人工生成的数据；历史外汇实验采用欧洲央行的每日参考汇率，无法代表实际可成交的报价。真实成交量实验的评估期较短，数据是否覆盖全市场成交量也尚未独立核实。

实际交易还会受到买卖价差、手续费、排队顺序和订单对市场的影响。项目没有完整模拟这些因素，价格与成交假设也有局限。模型中的冲击参数和风险偏好并未用实际交易校准。成交量预测更准确，也不必然意味着成本更低或订单更容易完成。

模型先求出允许小数股数的解，再转换为整数股数；相关下界用于检查结果，但不代表已证明整数方案是所有可行方案中最优的。
